# Предлагаемая серверная архитектура

**Не реализована в пакете.** Ниже — границы модулей и контрактов для настоящего приложения. Не выдавать эти схемы за существующие endpoints.

## Модули

`ingestion` → типизация и атомарная загрузка; `skill_projection` → snapshot + подтверждённая история; `eligibility` → жёсткие ограничения; `recommendations` → кандидаты, LLM и проверка; `participation` → переходы состояний и идемпотентность; `hr_analytics` → срезы с понятными знаменателями; `auth` → пользователь и scope доступа.

## Хранение

- employees: employee_id, роль, грейд, отдел, manager_id, цель, last_review_at, версия профиля.
- employee_skill_snapshots: employee_id, skill_id, level, assessed_at. База оценки не переписывается после каждого клика.
- skills и role_profiles: матрица требований, critical_skills, версия правил.
- events, event_skill_gains, event_prerequisites, event_audience, event_sessions: нормализованный каталог с отдельными датами сессий.
- participation: record_id, employee_id, event_id, session_id, enrolled_at, completed_at, due_at, status, completion_pct, assigned_by. В исходном CSV части этих полей нет; миграция требует политики, а не выдуманных значений.
- skill_gain_ledger: конкретное начисление и источник участия; уникальный ключ не позволяет применить одно завершение дважды.
- recommendation_runs: версия профиля и правил, snapshot, event_id, fact_refs, режим llm/fallback, задержка. Логи минимизированы; политика хранения согласуется.

## Предлагаемые API

| Запрос | Результат / ограничение |
|---|---|
| GET /me | Профиль вошедшего сотрудника, не произвольный ID |
| GET /me/trajectory | Цель, навыки, разрывы, provenance расчёта |
| PATCH /me/goal | Валидная цель; новая версия профиля |
| POST /me/recommendations | Проверенный список с fact_refs и mode |
| GET /events/{id} | Детали и доступность именно для текущего сотрудника |
| POST /participations | Валидация аудитории, сессии, роли и отсутствия повтора |
| PATCH /participations/{id}/complete | Разрешённый переход, идемпотентность, транзакционное начисление |
| GET /hr/skills | Агрегаты в разрешённом HR scope |
| GET /hr/employees | Поиск, фильтры, пагинация; нет публичного лидерборда |
| GET /hr/events | Сводка участия, период и знаменатели |
| POST /hr/import/validate | Предварительная валидация и список конфликтов |
| POST /hr/import/apply | Атомарное применение подтверждённого импорта |

## Безопасность

Проверять доступ на сервере в каждом endpoint. Подмена employee_id не должна раскрывать другого сотрудника. HR Business Partner — профессиональная роль, она сама по себе не является разрешением читать всю компанию. Scope HR и руководителя определяется отдельно.

Реальные ключи провайдеров хранятся только на сервере. Ограничить размер импорта, диапазоны, форматы, сессии и число строк; проверять ссылки до commit. При работе с архивом дополнительно защищаться от zip-slip и избыточной распаковки. Демо принимает уже распакованные JSON/CSV, поэтому ZIP-загрузчик в нём не реализован.

## Семантика выполнения

При in_progress обновлять существующее участие. Не создавать второе завершённое участие для того же занятия. В одной транзакции проверить состояние, обновить completed_at, записать ledger, изменить версию projection и зафиксировать результат. Повторный запрос с тем же idempotency key возвращает прежний результат без нового gain.

Расчёт skill projection должен быть детерминированным для одинаковых данных и бизнес-даты. Новая оценка навыков задаёт новую базовую точку; старые начисления нельзя повторно прибавлять к уже обновлённой оценке.
