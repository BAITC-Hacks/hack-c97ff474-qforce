# Контракт настоящего AI-слоя — предложение для реализации

**Статус:** проектный документ; API или LLM в данном пакете не реализованы. Референсные правила находятся в `02_prototype/assets/engine.js`. Их веса не обучены и не подтверждены скрытым тестом жюри.

## Разделение ответственности

Код: схема, права, бизнес-дата, восстановление навыков, границы навыков, допустимость событий, обновление участия. LLM: сопоставление нескольких факторов для выбора и объяснения среди допустимых кандидатов. Код после LLM: проверка ответа, ID, чисел, дат и ссылок на факты.

## Минимальный вход

```json
{
  "employee_id": "E0002",
  "profile_version": "snapshot-v1",
  "as_of_date": "2026-10-01",
  "current_role": "Backend Engineer",
  "current_grade": "Middle",
  "target": {"role": "Backend Engineer", "grade": "Senior"},
  "goal_is_inferred": false,
  "allowed_event_ids": ["EV_005"],
  "facts": [
    {"id": "F1", "factor": "grade", "value": "Middle"},
    {"id": "F2", "factor": "skill_gap", "skill": "SK_SYSTEM_DESIGN", "current": 1, "required": 4, "critical": true},
    {"id": "F3", "factor": "history", "event_id": "EV_005", "negative_participations": 1},
    {"id": "F4", "factor": "event_gain", "event_id": "EV_005", "skill": "SK_SYSTEM_DESIGN", "from": 1, "to": 2}
  ]
}
```

Это укороченный пример для протокола. В production список кандидатов и фактов строится из текущего snapshot автоматически; не копировать пример как фиксированную истину для всех профилей. ФИО, пол, почта и чужие профили для этой задачи не нужны.

## Предлагаемый ответ

```json
{
  "status": "recommendations",
  "employee_id": "E0002",
  "profile_version": "snapshot-v1",
  "recommendations": [{
    "event_id": "EV_005",
    "reasons": [
      {"factor": "grade", "fact_refs": ["F1"], "text": "Активность доступна для текущего грейда Middle."},
      {"factor": "skill_gap", "fact_refs": ["F2", "F4"], "text": "System Design растёт с 1 до 2 при требуемых 4; это критический навык цели."},
      {"factor": "history", "fact_refs": ["F3"], "text": "По этой активности есть один эпизод отрицательного участия; он учитывается, но не исключает критическое направление навсегда."}
    ]
  }],
  "mode": "llm"
}
```

Фразы в ответе — пример формата, а не готовый промпт с доказанной эффективностью. Минимум три **разных** фактора; три перефразированных предложения об одном навыке не подходят. Число рекомендаций — 1–3. Для `no_eligible_actions` — пустой список и структурированные причины, а не выдуманный event_id.

## Поствалидация

Проверить employee_id и profile_version. event_id должен входить в allowed_event_ids, быть уникальным и оставаться допустимым на момент ответа. Каждый fact_ref должен существовать и относиться к этому сотруднику/кандидату. Числа, сроки и прирост должны совпадать с вычисленными фактами. Нельзя доверять проверке чисел самой моделью.

Текст импортированных description/title не обладает правом менять системные инструкции. Данные не могут потребовать раскрыть чужой профиль, API-ключи или назначить событие, запрещённое фильтром. Неиспользуемые поля исключаются из контекста.

## Отказоустойчивость

Ожидание AI не блокирует загрузку профиля. Тайм-аут в рамках 10-секундного бюджета, ограниченные повторы, кэш по версии данных/цели/правил/бизнес-даты. Кэш сбрасывается после импорта и выполнения. При ошибке выдаётся проверенный baseline с `mode=rules_fallback` и такой же маркировкой в UI. При изменении версии профиля во время генерации устаревший результат не применять.

## Как оценивать

Отдельно измерять долю недопустимых ID, прохождение ограничений, число покрытых факторов, фактические ошибки объяснения и задержку. Для качества приоритизации использовать одинаковые заранее описанные профили и ручную проверку, не подменять тестирование субъективным «ответ звучит умно». Не заявлять качество на профилях жюри до их получения.

Референсный baseline: вклад закрытого разрыва умножается на 3 для critical_skill и на 1 для остальных; итоговый вклад умножается на 10; ограниченный штраф истории и небольшие добавки за известный формат и продолжение начатого. См. точную формулу в engine.js. Трудозатраты показаны пользователю, но в текущий score не входят; нет утверждения об оптимальном распределении рабочего времени.
