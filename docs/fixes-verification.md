# Исправления Career Quest и повторная проверка

23.09.2026. Продолжение [первоначального аудита ТЗ](career-quest-audit.md), выполненное по поручению исправить найденные ошибки и подключить настоящий OpenAI. Исходные отчёты сохранены как исторические; их оценка 7/10 описывает состояние до исправлений.

## Рабочее окружение

- Приложение: http://localhost:3000, API: http://localhost:3001, Swagger: http://localhost:3001/docs.
- Корневой `.env` создан локально: `LLM_PROVIDER=openai`, `LLM_MODEL=gpt-4.1-mini`, `ALLOW_EXTERNAL_LLM=true`, `LLM_TIMEOUT_MS=6000`. Ключ хранится только в локальной конфигурации backend; в отчёт его значение не включено.
- `.env` игнорируется Git. Проверено отсутствие точного ключа в доступных для Git файлах репозитория и в 171 файле локальной frontend production-сборки: [результат](fixes-secret-check.json). Docker build context не включает корневой `.env`.
- Рабочая БД `career_quest_full`: 200 сотрудников, 40 событий, 60 навыков, 2743 исходных записи истории. Старую БД `career_quest` и её volume сохранили. Demo employee связан с `E0001`.
- Обычный корневой Compose теперь по умолчанию загружает полный набор из `frontend/app/data`. Backend-only Compose и отдельные тестовые окружения используют fixtures. Чистый clone без ключа честно показывает подбор по правилам.
- Полные Docker-образы backend/frontend пересобраны; миграции и bootstrap завершились успешно, рабочие сервисы имеют healthcheck.

## Живая модель и объяснимость

В окончательном [live evaluation](fixes-live-evaluation.json) использован `gpt-4.1-mini`: 11 независимых синтетических сценариев, из них 9 требуют вызова модели. План вызывается один раз на сценарий и оценивается при бюджетах 1 и 3; два значения бюджета не считаются двумя независимыми AI-вызовами. Все предложенные ID допустимы, три обязательные категории факторов проверены по исходному контексту, fallback не потребовался. p50 около **1,53 с**, p95/максимум выборки около **3,66 с**.

В [HTTP-проверке рабочего сервера](fixes-live-http-results.json) принудительная генерация заняла **1,83–1,97 с** для E0001/E0090/E0028, включая HTTP и сохранение в PostgreSQL. Все три ответа имеют `AI_ASSISTED`, `aiUsed=true`, `model=gpt-4.1-mini`, `fallbackReason=null`. Проверены соответствие объяснений эффектам и чтение сохранённого набора.

[Финальные healthchecks](fixes-final-health.json) возвращают 200 для frontend/backend и подтверждают доступность БД. Поле health `liveVerified:false` означает, что сам healthcheck не вызывает платную модель; работа OpenAI подтверждена отдельными live/HTTP-результатами выше.

Финальный read-only Chromium на рабочем полном наборе: employee dashboard **120–168 мс** до критичных данных, HR overview **867–899 мс** до четырёх аналитических проекций, профиль E0090 с тремя сохранёнными AI-карточками **133–255 мс**; по три измерения. Проверены desktop/mobile, переключение языка, отсутствие page errors и горизонтального переполнения. [Итог с условиями замеров и reload на окончательном образе](audit-artifacts/frontend/fixes-main-ui.json), [HR-профиль и AI-карточки](audit-artifacts/frontend/fixes-main-ui/hr-E0090-recommendations-desktop.png), [казахский интерфейс на mobile](audit-artifacts/frontend/fixes-main-ui/hr-E0090-kk-mobile.png).

Во время более ранней проверки основные контейнеры получили Docker kill/stop; OOM не зафиксирован, источник команды не установлен. После восстановления повторно проверены все 200 профилей, готовность сервиса и сохранённые рекомендации E0090. Эта остановка не скрывается под метрикой успешных запросов. В конце временные тестовые сервисы остановлены, их данные сохранены; рабочий стек оставлен запущенным.

В [проверке полного набора](fixes-dataset-verification.json) без внешних вызовов: 158 READY, 16 NO_NEXT_GRADE, 26 NO_ELIGIBLE_ACTIVITIES. Пустые рекомендации в двух последних состояниях допустимы: система не выдумывает доступное обучение. Проверены последовательный gain/max_level, актуальные требования грейда, eligibility, отсутствие повторов и согласованность readiness.

Эта выборка не доказывает превосходство LLM над правилами: rules также проходят все заданные ожидаемые исходы. Модель нередко выбирает меньше трёх шагов; сравнивать суммарное закрытие дефицита без учёта количества/длительности обучения некорректно. Ожидаемый первый шаг на наших fixtures — regression-критерий, а не измеренная точность на неизвестных профилях жюри.

## Воспроизведение

Локальный полный запуск и отдельный свежий browser-стек описаны в [README](../README.md). Для backend из `backend/`: `npm test`, `npm run test:architecture`, `npm run lint`, `npm run typecheck`, `npm run build`. PostgreSQL integration/e2e требуют отдельной тестовой БД, как указано в [backend README](../backend/README.md).

Read-only проверка рабочего полного набора из корня:

```powershell
docker compose exec -T api node dist/scripts/verify-dataset.js --expected-employees 200
```

Rules evaluation из `backend/`:

```powershell
npm run evaluate -- --output docs/evaluation-report.json
```

Повторная платная проверка модели выполняется явно из `backend/`, с настроенным корневым `.env`:

```powershell
$env:RUN_LIVE_LLM = 'true'
node --env-file=../.env -r ts-node/register scripts/evaluate-recommendations.ts --output ../docs/fixes-live-evaluation.json
Remove-Item Env:RUN_LIVE_LLM
```

В CI добавлен актуальный frontend unit/typecheck/build и Chromium на отдельном fixture Compose; реальный ключ и live-проверка в CI не нужны.

## Остаточные ограничения

- Исходные навыки существующего сотрудника с прогрессом нельзя бесконтрольно перезаписать: `BASELINE_CONFLICT` и защита от backdated completed history сохраняются. Сообщение объясняет безопасный путь: новый `employee_id`, соответствующие ссылки истории и новые `record_id`, единый dry-run. Этот путь проверен integration-тестом.
- Импорт профиля не создаёт ему отдельный логин. Проверочный сценарий жюри проходит через HR: импорт → выбранный сотрудник → генерация → обоснование. Саморегистрация/SSO не реализованы.
- Неизвестный порядок грейдов требует явного `dataset-rules.json`. Нельзя корректно угадать порядок произвольных названий.
- RU/KK интерфейс добавлен; названия и описания каталога при отсутствии перевода остаются исходными, в том числе английскими. Независимая лингвистическая оценка казахского языка не проводилась.
- Pareto-проверка и валидация фактов не гарантируют глобально оптимальный план обучения. Readiness — покрытие требований, не вероятность повышения; HR-сигналы — наблюдаемые события, не диагноз мотивации.
- Не предоставлены исходный README стартового кита и скрытые профили жюри; их прохождение не утверждается. Локальная проверка времени не является нагрузочным тестом 200 одновременных пользователей или SLA внешнего сервиса.
- Опциональные валюта, награды, менторские механики и календарь не добавлялись: они не заменяют обязательное качество подбора.

Все подтверждённые программные дефекты первоначального аудита адресованы изменениями и регрессионными проверками. Это относится к перечисленным сценариям, а не является гарантией отсутствия любых ошибок.
