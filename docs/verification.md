# Проверка интеграции Career Quest

> Этот отчёт относится к интеграции до последующего аудита и исправлений. Актуальная проверка полного набора, браузера и живого OpenAI: [fixes-verification.md](fixes-verification.md).

Проверено 23 сентября 2026 года. Окружение: Windows, Node.js 24.20.0 для локальных проверок; Docker Desktop с Linux containers; образы Node 22.20.0 и PostgreSQL 17.6. Браузерные проверки выполнены в Chromium против production-сборки Nuxt в Docker, с реальным NestJS API и PostgreSQL.

## Браузерные сценарии

- Вход сотрудника; профиль на экране сравнивается с реальным API. Генерация рекомендаций и отправка обратной связи сохраняются на сервере.
- Прямое открытие карточки активности, запись на неё, завершение и отображение `trajectoryBefore`, `trajectoryAfter`, `changedSkills` из ответа backend. GET профиля и истории подтверждает результат. Повторный запрос завершения не увеличивает навыки второй раз.
- Перезагрузка страницы результата перечитывает сохранённый `completionResult` из истории. Проверки не зависят от локально вычисленного прироста или localStorage.
- Реальный 403 на HR API для сотрудника и запрещённый HR-маршрут; невалидный JWT вызывает реальный 401 и возвращает к форме входа. Неверный пароль не создаёт сессию.
- Пустой каталог по фильтру, реальный 404 неизвестной активности, состояние загрузки и восстановление после ошибки.
- Отказ записи отображается как ошибка, страница не сообщает об успехе, история backend остаётся прежней.
- HR-сводка сравнивается с `/hr/overview`; проверены список сотрудников, ограничения пагинации, точный фильтр подразделения, пустое состояние, профиль сотрудника и перезагрузка прямой ссылки.
- Некорректный multipart-пакет отклоняется; допустимый пакет проходит dry-run. Повторное применение идентичного fixture не изменяет существующие профили; отчёт `APPLIED` перечитывается после обновления страницы.
- Desktop 1440 px и mobile 390 px: обзор сотрудника, профиль, траектория, каталог, участие; HR-сводка, сотрудники, аналитика участия, импорт. Проверены отсутствие горизонтального переполнения страницы и работа мобильного меню; просмотрены скриншоты. Широкие HR-таблицы прокручиваются внутри панели.

Три отрицательных UI-проверки намеренно перехватывают сетевой ответ: недоступная траектория, отказ записи, недоступная HR-сводка. Это изолированные тесты ошибок; успешные бизнес-сценарии используют реальный API. Рабочий frontend не содержит mock-fallback.

Тесты лежат в `frontend/tests/e2e/`, конфигурация запрещает удалённый хост для E2E с изменением данных. Учётные записи можно задать через `E2E_EMPLOYEE_USERNAME`, `E2E_EMPLOYEE_PASSWORD`, `E2E_HR_USERNAME`, `E2E_HR_PASSWORD`; адрес — `E2E_BASE_URL`. Для описанного покрытия нужен явно выбранный набор backend fixtures. Отчёт Playwright и скриншоты создаются в `frontend/playwright-report/` и `frontend/test-results/`, исключённых из Git.

## Сеть и сохранность данных

Проверены HTTP 200 для frontend, прямых внутренних URL, `/health/ready`, backend `/health/ready`, `/docs` и `/openapi.json`. Proxy сохраняет `/api/v1`, POST body, Authorization, query-параметры пагинации и статусы 401/403. Приватный адрес `http://api:3001` не попадает в HTML клиента. Frontend работает от пользователя `node`; PostgreSQL не публикует порт хоста, HTTP-порты доступны на loopback.

После первой записи и завершения сравнивались точные данные профиля `fixture_person_a` и все пять записей его истории до и после `docker compose restart postgres api frontend`: различий нет. JWT сохранил работоспособность, healthcheck и HTTP-маршруты восстановились. Последующий финальный браузерный прогон также сохранил ещё одно завершение в этой локальной БД. Повторный bootstrap показал `create=0`, `update=0`, `skip=31`, не сбрасывая online-прогресс.

Используется прежний volume `career-quest_postgres_data`; volumes не удалялись. Тестовые изменения затронули только локальные синтетические fixtures и изолированную тестовую БД. Стек оставлен запущенным.

## Минимальные изменения backend и границы проверки

У `GET /employees/{id}/recommendations/latest` отсутствовал Swagger query-параметр `locale`, хотя DTO и runtime его поддерживали. Расхождение воспроизведено, добавлена аннотация и усилен существующий e2e-тест. Бизнес-логика и API-поведение не изменены. Backend Compose получил локальные значения по умолчанию и optional env-файлы для общего запуска; его миграции, bootstrap, сеть и volume сохранены.

Подробности контракта: [api-integration.md](api-integration.md), фактический снимок [openapi.json](openapi.json), журнал [api-contract-verification.json](api-contract-verification.json).

Самостоятельная регистрация, смена пароля, редактирование профиля и карьерной цели не предоставлены существующим API и явно обозначены как недоступные. Импортированная история может не иметь подробного результата изменения навыков. Внешняя LLM не проверялась и по умолчанию выключена: используется маркированный сервером подбор по правилам. Проверки не подтверждают production SSO, работу с неизвестным внешним датасетом, нагрузочную устойчивость или совместимость с Firefox/Safari.

Исходные HTML-прототипы `app/pages/test.vue` и `main.html` сохранены в `frontend/design-reference/`: первый содержал некорректный для Vue HTML и мешал сборке. Эти макеты исключены из рабочей маршрутизации и образа; существующие автоматические тесты сохранены.
