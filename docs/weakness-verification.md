# Повторный аудит Career Quest: исправления и проверка

Проверено 23 сентября 2026 года на Windows, Docker Desktop и Chromium. Это отчёт о текущих исправлениях, а не оценка скрытых профилей жюри. Исходные данные, каталог и семь языков интерфейса сохранены. Основное приложение работает на `http://localhost:3000`, API — на `http://localhost:3001`.

## Что изменено

| Слабое место | Исправление и проверка |
| --- | --- |
| Жадный выбор терял эффект из-за порядка `gain/max_level` | Планировщик моделирует целую последовательность из 1–3 шагов с пересчётом навыков после каждого. Проверен пример: навык 1, сначала +1 с потолком 2, затем +2 с потолком 4; обратный порядок хуже. |
| Первые десять кандидатов ограничивали AI; подготовительные курсы исчезали | Рассматривается весь каталог. Подготовительный шаг может развить навык входного требования и открыть следующий курс. Его объяснение ссылается на реально выбранный последующий шаг. Есть сценарий с необходимым курсом за пределами первых десяти. |
| Несовместимые даты и условия отдельных рекомендаций | Каждый шаг повторно проходит проверку аудитории, входных требований, повторяемости, эффекта и хронологии. Даты рассчитываются с точностью до дня и минимальной физической длительностью. Ограничения расписания описаны ниже. |
| Модель могла вернуть неверную последовательность или факты | В конечном контракте модель выбирает только `planId` из проверенных планов. Сервер восстанавливает шаги и факты, повторно проверяет план; при сбое используется явно отмеченный подбор по правилам. AI не сочиняет числовые обоснования. |
| Объяснения перечисляли факторы без сравнения | Добавлены последовательность, прогноз дат, фактическое изменение навыков и сравнение с другим допустимым планом по эффекту, длительности и истории. Учтены релевантные добровольно выбранные активности; назначенное и обязательное обучение не выдается за предпочтения сотрудника. |
| Нет сценария при исчерпанном каталоге | Сотрудник видит дефициты и может создать сохраняемую заявку. HR видит очередь, отвечает, сотрудник получает ответ. Версии защищают от устаревших ответов и повторных запросов. Заявка не начисляет навыки и не отправляется во внешние сервисы. |
| HR смешивал обязательную активность с самостоятельным участием | Разделены обязательное, необязательное и неклассифицированное участие с собственными знаменателями. Наблюдаемые сигналы не объявляются диагнозом мотивации. Покрытие учитывает найденные подготовительные цепочки. |
| Смена языка или feedback могли убрать сохранённые рекомендации | Один путь чтения последнего подбора с языковым fallback, включая ответ `null`. Браузерная проверка смены языка и feedback проходит. |
| После записи и завершения интерфейс ждал необязательные запросы | Переход зависит от критических данных; дополнительные чтения загружаются отдельно. Сохранены обработка ошибок и фактическое завершение на сервере. |
| Ошибка одного HR-запроса скрывала весь экран | Четыре блока загружаются независимо, каждый имеет ошибку и повтор. Пагинация обновляет собственный блок. Проверена искусственная ошибка одного HTTP-запроса. |
| Проверочные профили могли пересечься с исходными ID | Режим жюри создаёт отдельные ID в пространстве имён, переадресует ссылки истории, требует проверенный предварительный отчёт. Изменение общей даты частичным пакетом отвергается. Исходные профили и общий каталог не перезаписываются. |
| Сокращённый профиль из ТЗ и вход нового сотрудника не поддерживались | Добавлен нормализатор сокращённого профиля с видимыми допущениями, поиск по ID/имени и выдача отдельного логина HR. Пароль показывается только при создании, хранится как scrypt-хеш; повторное создание не сбрасывает существующий пароль. |
| Запуск AI требовал ручной настройки нескольких параметров | `./start-demo.ps1` использует существующий локальный `.env` либо предлагает скрытый ввод ключа. `-Rules` запускает полный набор без AI; `-CheckOnly` проверяет конфигурацию без платного вызова. Настоящая работа провайдера проверена отдельно. |
| Успешные собственные тесты выдавались за достаточное доказательство качества | Добавлен независимый исчерпывающий числовой эталон для малых сценариев. Отдельно сравниваются одинаковые бюджеты в 1 и 3 шага, длительность, допустимость, эффект и факты. Живые вызовы, fallback и ограничения выборки показаны явно. |

Итого 191 успешная автоматическая проверка, отдельно — оценки алгоритма, живые вызовы AI и проверка полного набора. Браузерные тесты выполнялись на отдельном окружении с fixtures и отключённой моделью, чтобы не смешивать проверку интерфейса с оценкой провайдера. В одном полном прогоне защитный лимит входа вернул HTTP 429. Тест входа теперь один раз соблюдает серверный `Retry-After`; лимит приложения не ослаблен. Последний полный прогон успешен, задержка отражена в [JSON Playwright](weakness-browser-results.json).

### Качество рекомендаций

[Проверка правил](weakness-rules-evaluation.json): 18 авторских сценариев, каждый отдельно с бюджетом в 1 и 3 шага. У нового планировщика во всех сценариях допустимые последовательности, проверенные факты и достижимый максимальный взвешенный эффект. Это утверждение относится к небольшим тестовым каталогам и указанному бюджету.

При бюджете 3 шага прежняя жадная стратегия дала допустимую последовательность в 11/18 сценариях; новая — в 18/18. `previous-greedy` воспроизводит прежний способ выбора с текущими общими политиками, а не запускает старый Git-коммит. Эталон независимо перебирает допустимые последовательности и считает прирост; он не оценивает мотивацию, качество курса или предпочтения человека.

[Конечный контракт `planId`](weakness-live-planid-evaluation.json) проверен девятью настоящими запросами `gpt-4.1-mini` на пяти выбранных сценариях из общей библиотеки. Пустой вариант не отправлялся модели. Все девять ответов допустимы, факты проверены, fallback нет; время 1,2–1,4 с. Совпадение первого шага с авторским предпочтением — 4/4 для бюджета 1 и 3/5 для бюджета 3: модель иногда выбирала другой допустимый компромисс истории и календаря. **Преимущество LLM над сильным планировщиком по правилам этими измерениями не доказано.**

[Предыдущий живой прогон](weakness-live-evaluation.json), 31 вызов, сохранён как история до перехода на `planId`: в нём был один fallback. Он не подменяет проверку конечного контракта. Дополнительные три запроса через настоящее приложение на полном наборе записаны [отдельно](weakness-live-http-results.json).

[Проверены все 200 сотрудников](weakness-dataset-verification.json): 374 карточки, 506 фактов дефицита, ошибок расчёта нет; поиск завершился для всех профилей. План доступен для 159 сотрудников, у 16 нет следующего грейда, у 25 каталог не даёт допустимого полезного пути в пределах трёх шагов. Подготовительная цепочка открыла путь ещё одному сотруднику относительно предыдущего аудита. Для оставшихся случаев работает заявка HR; новые курсы не выдумывались.

Чистый расчёт планировщика: p50 2,4 мс, p95 14,1 мс, максимум 35,6 мс. Эти числа не включают БД, HTTP, браузер и AI.

## Что остаётся ограничением

- Нехватка обучения у 25 сотрудников требует решения HR и пополнения каталога. Заявка обеспечивает рабочий выход из тупика, но сама не закрывает дефицит навыков.
- Оригинальные README организаторов и скрытые профили жюри не были доступны. Поддержка сокращённого профиля проверена на собственных данных; допущения не скрываются.
- Завершение курса подтверждает сам сотрудник. Это явно обозначено; интеграции с LMS и независимой аттестации нет. Расчёт прироста не доказывает реальное приобретение навыка или рост вовлечённости.
- Календарь использует даты и минимальную длительность `ceil(hours / 24)` с минимумом в один день. Рабочее расписание, выходные, часовые интервалы и реальная доступность сотрудника неизвестны.
- Поиск ограничен тремя шагами, числом последовательностей и временем. На большом стороннем каталоге неполный поиск раскрывается в диагностике; исчерпание времени без найденного плана возвращает ошибку, а не ложное «нет подходящего обучения».
- Служебный пароль показывается один раз, но не является автоматически истекающим одноразовым паролем. Корпоративные SSO, MFA и восстановление пароля не добавлялись.
- Подробные объяснения занимают много места в карточках. Все факты читаемы; это остаётся возможностью для дальнейшего упрощения интерфейса.
