# Аудит frontend Career Quest — 23.09.2026

> Исторические находки до исправлений. Текущее состояние и повторная проверка: [fixes-verification.md](fixes-verification.md).

Проверено соответствие кейсу **Career Quest** из предоставленного ТЗ, исходники работающего Nuxt frontend, существующие проверки и дополнительные сценарии в Chromium. Продуктовый код не изменялся. Проверки выполнялись только на отдельных локальных стеках аудита, без внешних LLM и передачи датасета наружу.

## Что действительно работает

- Профиль, требования следующего грейда, навыки, критические разрывы, формула прогресса и история подключены к backend; вместо ошибки не подставляются локальные демоданные.
- Сотрудник получает 0–3 рекомендации, видит объяснение, ожидаемый прирост, предупреждение об устаревшем наборе. На странице рекомендаций честно указано, использовался ли AI.
- Запись, завершение, повторное завершение, изменение навыков, сохранение после перезагрузки и обратная связь проходят существующий сквозной тест.
- HR видит сводки, разрывы, наблюдаемые сигналы участия, сотрудников и историю. Есть разграничение маршрутов employee/HR, а API отдельно запрещает сотруднику HR-запросы.
- Импорт имеет dry-run, диагностику, запрет применения непройденного пакета и сохранённые отчёты. HTTP 200 с REJECTED правильно показывается как отказ.
- В интерфейсе нет публичного рейтинга людей, баллов за обязательные процессы и давления на участие; есть отказ и прерывание.
- На проверенных desktop/mobile маршрутах нет горизонтального переполнения. Локальная история из `frontend/app/data` не включена в публичный JS-бандл: поиск E0001, имени первого профиля, R000001, EV_001, SK_PYTHON не дал совпадений после production build.

## Подтверждённые недостатки

### F1. Высокий: жюри не может проверить рекомендации произвольного загруженного профиля через UI

**ТЗ:** жюри загружает проверочные профили и историю, затем оценивает качество рекомендаций.

**Факт:** `/hr-employee?id=...` показывает навыки, цель и историю, но не рекомендации и не кнопку их генерации. Компонент `frontend/app/components/CqProfile.vue:4` вызывает общий загрузчик, который даже читает `recommendations/latest` (`frontend/app/composables/useCareer.js:88`), однако шаблон профиля их не отображает. Маршрут `/recommendations` запрещён HR и перенаправляет на `/hr-dashboard` (`frontend/app/middleware/auth.global.js:18`). Сотрудник связан с единственным `employeeId` своей учётной записи; произвольный ID через этот экран выбрать нельзя.

**Воспроизведение:** войти `hr`, открыть профиль любого сотрудника в `/hr-people`. У fixture_person_a число карточек рекомендаций и ссылок на рекомендации равно 0; единственная кнопка на странице — «Выйти». Это не означает, что сервер не умеет генерировать рекомендации для него: ограничение именно в пользовательском сценарии UI.

Дополнительно на **полном датасете** через API HR сохранены 3 рекомендации для E0090 (HTTP 201), затем открыт `/hr-employee?id=E0090`: по-прежнему 0 карточек и 0 ссылок на подбор. Результат и снимок экрана сохранены.

**Последствие:** после успешного импорта потребуется Swagger/API либо заранее подготовленные учётные записи. На защите основной must-have нельзя показать непрерывным сценарием приложения.

**Исправление:** добавить HR-просмотр/генерацию рекомендаций конкретного сотрудника (read-only для участия), сохраняющий его ID; показать объяснение и историю рядом. Зафиксировать сценарий «импорт нового ID → профиль → подбор» отдельным E2E.

### F2. Высокий: обычный запуск с fixtures отклоняет полный существующий датасет из четырёх файлов

**ТЗ:** вход `employees.json`, `events.json`, `skills.json`, `activity_history.csv`, объём 200/40/60 и 24 месяца истории.

**Факт:** эти данные уже лежат в `frontend/app/data`: **200 сотрудников, 40 событий, 60 навыков, 2743 записи истории, 2024-10-01—2026-09-30**. Runtime их не использует; они читаются только устаревшими тестами `tests/engine.test.js`. Стандартный запуск README загружает 6 backend-fixtures.

**Воспроизведение в браузере:** HR → Импорт → выбрать все четыре файла из `frontend/app/data` → «1. Проверить пакет». HTTP 200, `status: REJECTED`, **32 ошибки UNKNOWN_GRADE_ORDER** по Junior/Middle/Senior/Lead. В отчёте остались правила fixtures `gradeOrder: [Apprentice, Practitioner, Expert]`, `repeatableActivityIds: [FX_SPEAKING]`. Dry-run занял 217 мс. Изменений профилей нет.

**Причина:** импорт использует текущие dataset rules; позиции новых грейдов определяются `rules.gradeOrder.indexOf(g.grade)` в `backend/src/modules/dataset-import/infrastructure/parsers/dataset.parser.ts:58`; незнакомый порядок отклоняется в строке 66.

**Граница вывода:** это ловушка перехода с стандартного демо на полный набор через UI, а не доказательство, что backend вообще не поддерживает полный набор. Отдельный `DATA_MODE=input` bootstrap на чистой БД с теми же четырьмя файлами успешно загружает 200/40/60/2743; root-аудит подтвердил это отдельно.

**Исправление:** сделать документированный и проверенный default/demo сценарий для полного набора; предоставить правильный rules-файл/миграцию и объяснить необходимость правил до импорта. На защите не начинать с fixtures, несовместимых со starter kit по грейдам.

### F3. Средний: ссылка на активность HR ведёт на другую страницу

В `frontend/app/pages/hr-events.vue:165` название активности — ссылка `/event?id=...`. В `frontend/app/middleware/auth.global.js:21` HR запрещён `/event`. Браузер подтвердил клик `/event?id=FX_BASELINE_HISTORY` → фактически `/hr-dashboard`, без карточки и без объяснения.

**Исправление:** отдельная read-only карточка для HR либо разрешённый HR режим страницы события без кнопок записи сотрудника. Тестировать клики по ссылкам HR-таблиц, а не только отображение таблиц.

### F4. Средний: отказ хранилища рекомендаций скрывает даже исправный профиль

В `frontend/app/composables/useCareer.js:84` профиль, траектория, полная история, рекомендации, eligibility и все каталоги загружаются одним `Promise.all`; запись профиля в store происходит только после успеха всего набора (`:99`).

**Воспроизведение:** перехватить только `/employees/*/recommendations/latest?*` и вернуть 503, затем открыть `/profile`. Хотя endpoint профиля и траектория отвечают успешно, заголовок «Мой профиль и навыки» отсутствует; весь контент заменён ошибкой рекомендаций. Снятие перехвата и «Повторить запрос» восстанавливает профиль (116 мс в fixture-проверке).

**Последствие:** один независимый сбой рекомендации/истории/каталога отключает весь employee-контур; нет частичного показа уже доступных данных. Каждый переход повторно грузит весь комплект и всю историю, даже если экран их не использует.

**Исправление:** раздельные состояния для профиля/траектории, каталога, истории и рекомендаций; retry отдельного блока. Это уменьшит связанность отказов и лишние запросы. Нормальный режим на локальном стенде при этом быстрый — не следует выдавать этот fault injection за измеренное нарушение SLA.

### F5. Низкий / опциональный: нет казахского интерфейса и выбора языка

`frontend/app/layouts/default.vue:78` выводит статичное RU; `frontend/app/pages/settings.vue:33` предлагает только русский; API-запросы в useCareer жёстко используют `locale: ru`. Предпочтительный язык импортированного сотрудника не выбирает UI/рекомендации. ТЗ относит качественную локализацию RU/KK к опциональной части, поэтому это потерянная дополнительная возможность, а не провал must-have.

### F6. Средний: зелёный тестовый прогон преувеличивает покрытие требований

38 тестов `engine.test.js` проверяют прежний локальный движок, который приложение больше не использует. Из актуальных unit-тестов 15 проверяют transport/session/import sequencing. 12 E2E проходят на шести fixtures; они не проверяют полный starter kit, произвольный imported employee → рекомендации и переход HR по ссылке события. В основном employee E2E часть рекомендаций зависит от `if (set.recommendations.length)`; сохранённое предыдущее завершение может заменить новую запись/завершение на повторном прогоне. Поэтому «12 passed» означает корректность этих конкретных проверок, а не доказанное соответствие всем пунктам ТЗ.

## Вывод по frontend

Основной путь уже работает на серверных данных, UI аккуратен и различает ошибки, пустой ответ, stale и fallback. Главные препятствия защите находятся в **демонстрации must-have на новых профилях** и **переключении стартового набора с fixtures на данные кейса**. После них важны сломанная ссылка HR и независимая загрузка блоков. Не стоит тратить время на валюту/награды раньше этих исправлений: геймификация в ТЗ необязательна.
