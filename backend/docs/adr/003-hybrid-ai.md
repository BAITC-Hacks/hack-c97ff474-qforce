# ADR 003: AI выбирает в рамках проверяемых фактов

Статус: принято.

Контекст: минимальный навык не определяет полезный шаг; произвольным activityId/числам/объяснениям модели доверять нельзя.

Решение: сервер фильтрует eligibility, строит shortlist/evidence. Модель выбирает и упорядочивает 1–3 существующих ID; Zod и semantic validator проверяют ответ. Числа, caps и фактическое объяснение формирует сервер. Fallback явный: RULES_FALLBACK, aiUsed=false, причина диагностики.

Последствия: AI влияет на выбор при успешном провайдере. Timeout/refusal/невалидность не ломают сценарий. Контекст версионируется и повторно проверяется после сети. Внешняя передача по умолчанию запрещена; ключ не равен разрешению. Fake/rules tests не доказывают live AI: нужен успешный opt-in запрос реальной модели.

Адаптеры реализуют LlmRecommendationPort через OpenAI Responses API и native Ollama API. Ollama проверяется через /api/tags и /api/show до передачи контекста: нужны completion capability и сведения о локальных GGUF-весах; cloud aliases и remote_host/remote_model требуют отдельного разрешения. Выбор выполняется через /api/chat с JSON Schema. Общий deadline use case — 10 секунд, timeout модели — не более 6 секунд; недоступность согласованного хранилища по deadline возвращает явный 503, а не выдуманный сохранённый результат.
